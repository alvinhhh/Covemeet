# Initial API contract

Same-origin `/api`, JSON. Mutation calls send `Content-Type: application/json` and `X-Requested-With: MeetingPlatform` (the stable protocol marker). The recording attachment route also accepts a native form POST as described below. Cookie-backed HTTP-only sessions. Errors `{error: string}`. All GETs no-store. No client-supplied tenant. Single installation/tenant for this first implementation.

- `GET /api/config` → `{edition:'hosted'|'self-hosted',brandName,recordingAvailable,mediaAvailable,creationRequiresKey}`.
- `POST /api/meetings` body `{title,hostName,password,mode:'meeting'|'webinar',customCode?,creationKey?}` → `{code,hostToken,guestUrl}`. Never persist plaintext hostToken in local storage. Navigate `/host/CODE#TOKEN` and immediately exchange/clear fragment.
- `POST /api/meetings/:code/host` `{token}` → `{participantId}` + session cookie. Token single use.
- `POST /api/meetings/:code/join` `{name,password}` → `{participantId}` + session cookie; lobby by default.
- `GET /api/meetings/:code/state` → `{meeting:{code,title,mode,locked,ended,recordingAllowed,createdAt},me:{id,name,role,status,audioAllowed,videoAllowed},participants:[{id,name,role,status,audioAllowed,videoAllowed}],messages:[{id,name,text,createdAt}],recordings:[{id,status,createdAt,expiresAt?}],revision}`. Guests see admitted participants and themselves; hosts also see waiting/rejected/kicked/banned. Status waiting/admitted/kicked/banned/left. Role host/participant/viewer.
- Poll state every 2s; 401/403 means show a join page, never silently create a new session.
- `POST /api/meetings/:code/participants/:id/action` `{action:'admit'|'kick'|'ban'|'allow-audio'|'block-audio'|'allow-video'|'block-video'|'promote'|'demote',banIp?:boolean,banDevice?:boolean}` → `{ok:true}`.
- `PATCH /api/meetings/:code` `{locked?:boolean,recordingAllowed?:boolean}` → `{ok:true}`; host only.
- `POST /api/meetings/:code/end` `{}` → `{ok:true,cleanupPending}`. Returns 202 while media, phone or recorder cleanup is unresolved; 200 after confirmation. State polling exposes `meeting.cleanupPending` until cleanup finishes.
- `POST /api/meetings/:code/leave` `{}` → `{ok:true}`.
- `POST /api/meetings/:code/messages` `{text}` → `{ok:true}`.
- `POST /api/meetings/:code/media` `{}` → `{token,url,mediaIdentity}`; only admitted sessions. URL is the gateway signaling endpoint. Client uses `autoSubscribe:false` and explicitly subscribes to admitted participants' audio and at most 16 visible video tiles including local video. Screen shares receive bounded priority; remaining tiles are paginated. Webinar video excludes audience placeholders. Camera and microphone start off.
- `POST /api/meetings/:code/host-email` `{email}` → `{ok:true}` sends OTP. `POST /api/meetings/:code/verify-email` `{otp}` → `{ok:true}`.
- `POST /api/meetings/:code/recordings` `{}` starts optional recording if available, allowed and host email verified. `POST /api/meetings/:code/recordings/:id/stop` `{}` stops. `POST /api/meetings/:code/recordings/:id/link` `{}` → `{url,expiresAt}` emails separate password. No plaintext password in response. `POST /api/meetings/:code/recordings/:id/revoke` `{}` revokes.
- `/download/:code#token` UI accepts password; `POST /api/meetings/:code/download` `{token,password}` returns decrypted media as attachment, requires host session. The UI uses a native URL-encoded form POST to stream the attachment to the browser without buffering the file in JavaScript. Only this route accepts that form type without the custom header, and only with the exact configured meeting `Origin`. Duplicate/unknown fields, missing/cross-origin requests and non-host sessions are rejected. Token and password stay in the POST body; the fragment is removed before rendering. The page uses `Referrer-Policy: same-origin`: other origins receive no referrer, and native form POSTs retain the same-origin `Origin` header. `no-referrer` would make that header `null` under the [Fetch origin algorithm](https://fetch.spec.whatwg.org/#append-a-request-origin-header); null origins remain rejected. The response frame permits forms and downloads but no scripts. Failed form requests retain their HTTP status and return escaped JSON inside a script-free HTML document, so the frame can display the error; JSON API callers still receive JSON.

Meeting state also includes `participantLimit`, optional `startedAt` and `deadlineAt` (epoch milliseconds). The fixed session clock starts on the first host entry. Reconnecting or refreshing a paid entitlement does not extend it. Finished recording downloads remain available after an ordinary meeting end; revoking the host account removes that access too.

Each participant in `me` and `participants` has a logical `id`, a `mediaVersion` and a current `mediaIdentity`. Use the logical ID for host actions, chat, room assignments and usage. Use `mediaIdentity` to match SDK participants, tracks, names and speaking indicators. A permission or removal fence rotates the media identity with the version and retains the retired identity until cleanup is confirmed. Delayed cleanup targets that retired identity. Phone grants use physical media identities in `subscribeParticipantIds`; phone dialog and participant IDs remain logical.

Unmetered gateways persist a connection ID and a 15-second presence deadline before opening upstream signaling. Only the current connection can renew that deadline or start cleanup. The existing worker fences expired connections and retries removal; logical admission stays available for reconnect after cleanup. Hosted gateways use the participant meter's existing presence rule. Database or SFU outages can delay confirmed physical removal.

Deploy the API and matching browser bundle together, stop older gateway processes and reload older browser tabs. Persisted participants without `mediaIdentity` retain their logical ID as their media identity until their next fence; clients must only use that fallback when the field is absent.

The hosted adapter uses authenticated private endpoints for account authority, named host entitlements and meeting creation. Entitlements carry a monotonic revision, a short expiry and the allowed hosts for one billing owner. New customer meetings require a current grant; self-hosted installations do not require subscriptions. Customer plans currently cap rooms at 100 total people, two hours, one room per host and at most two rooms per Teams account. Capacity remains reserved until cleanup is confirmed.

Hosted grants also carry `quota:{anchorAt,participantSecondsPerMonth,recordingSecondsPerMonth?,downloadBytesPerMonth?}`. An enabled grant requires a quota; a disabled grant may carry `null`, which does not erase earlier usage. The first paid UTC anniversary is permanent for the billing owner. Monthly boundaries clamp that original day in shorter months: January 31 resets on February 28 or 29, then March 31. Changing the subscription, seats or grant revision does not reset usage.

Participant allowance starts when the upstream meeting signaling connection opens. Setup, muted time and a 15-second reconnect window count; waiting-room time and attempts whose upstream connection never opens do not. Reconnects and breakouts use the same logical participant identity for accounting. This measures access time, not decoded video or RTP duration. The store reserves up to 30 seconds before access and renews from live gateway presence. Cleanup keeps unused time reserved until disconnection is confirmed. Existing funded participants can continue while another participant is being removed; new allocations wait for that cleanup. A guest exhausting its reserved time is disconnected; the host exhausting its time ends the meeting.

`POST /api/internal/hosted/usage` accepts `{billingOwnerId}` with the same private machine authentication as other hosted controls. It returns `{ok:true,window:{start,end},participantSeconds:{limit,used,reserved,available},recordingSeconds:{limit,used,reserved,available},recordingDownloadBytes:{limit,used,available},asOf,blocked}`. Times are epoch milliseconds; participant and recording-time counters are integer seconds and download counters are integer bytes. Used and reserved time round up; available time rounds down from the stored millisecond amounts. Clients must not recalculate available time from the rounded display counters. Missing paid usage history returns 404 with code `USAGE_UNAVAILABLE`; connection or storage failures are not an empty balance. Hosts receive the same aggregate in `meeting.usage`; guests do not. The hosted portal resolves the billing owner from the signed-in account and rechecks membership before returning the aggregate.

A bound recording reserves time under its original billing owner's lock before starting Egress. Missing `recordingSecondsPerMonth` means zero; new starts require a current enabled grant. The entire elapsed interval plus prepaid time remains reserved while the job is unresolved. Provisional start timestamps may change; the earliest observed start keeps the hold conservative. Only matching terminal Egress proof settles job time once, using top-level `startedAt` and `endedAt`, including recorder startup and shutdown rather than MP4 duration. Time crossing a monthly boundary is split across the original owner's fixed windows. Unknown starts, missing jobs and failed stop requests retain their holds and block further recording allocations; they are not refunds. Unbound self-hosted and legacy rooms keep their existing recording behavior.

A hosted recording download debits its full declared plaintext size atomically against the meeting’s original billing owner before any plaintext is returned. Retries count again; canceled or interrupted downloads receive no refund. Wrong credentials, an unreadable initial ciphertext frame, or failed current-host authorization consume no allowance. The decryptor authenticates each frame and rejects bytes beyond the declared size before emitting them; complete-file integrity is verified at EOF. Closing the HTTP connection during preparation cancels pending storage reads and denies admission before debit. A disconnect after admission retains its debit. Download usage has no reserved counter and does not consume participant-minutes.

Download allowance uses the same monthly window as participant usage. Missing `downloadBytesPerMonth` means zero for old bound grants; a newer grant must supply it before positive-size downloads. Ordinary meeting end, hosting-lease expiry and cancellation preserve download access within retention and the retained allowance. Revoked accounts/recordings still fail. Explicitly unbound legacy and self-hosted rooms have no hosted quota. Authorization, link expiry, the seven-day retention deadline, recording metadata and available allowance are rechecked together at admission. Revocation or expiry after admission does not cancel an already streaming download.

These allowances do not invoice overages or establish a bandwidth/spending cap. If SFU control is unavailable, signaling denial alone cannot guarantee that an existing direct media connection has stopped. Unconfirmed cleanup retains its reservation and blocks new allocations. The installed Egress API has no per-job duration cap; worker or control-plane outages can overrun a recording reservation before stopping is possible. Storage quotas remain separate work. Recording-time source checks and a six-phase real-recorder runtime fixture passed. The observed shutdown overran its funded deadline; see the requirements ledger for counts and scope.

Phone integration and 100/1000 media capacity require separate runtime validation.
