# Requirements and release gates

Reviewed against the complete [infrastructure plan](infrastructure-plan.md) and [security controls](security-controls.md), 5 October 2026. This is an implementation ledger, not a completion certificate. **External production release remains blocked.** Tests establish only their named behavior at their tested scope; an architectural setting or passing unit test does not establish production capacity, legal compliance or resilience.

Evidence is identified by checked-in implementation/tests or a reproducible validation command. Runtime reports remain local and excluded from Git because future reports can contain operational metadata. Record exact image identities, versions, timestamps and test configuration before using results as release evidence.

Current hosted plans use expiring named-host grants, 100-person meetings and one active room per named host. Personal has a two-hour deadline; Teams has an eight-hour deadline, 1,000 webinar viewers plus ten stage members, and one concurrent room per paid seat. New grants provide 100 meeting hours per paid seat each month, pooled for Teams. Browser and phone admissions share the total and webinar-viewer checks. Ending a meeting returns pending status until media, recorder and phone cleanup is confirmed; reservations stay occupied during that interval. Self-hosted operators can configure room size and session length without a subscription. The participant-meter baseline passed local typecheck, 301 tests (ten opt-in skips) and build. Separate runs passed six disposable PostgreSQL checks, eleven meter tests and one real WebSocket gateway regression. The earlier deployed deadline fixture and the five-phase runtime quota-exhaustion fixture below passed. Recording-time production validation, storage deployment validation, production media-failure handling and migration of old unbound hosted rooms remain open.

## Authoritative technical boundaries

- [TLS 1.3, RFC 8446](https://www.rfc-editor.org/rfc/rfc8446), [WebRTC security, RFC 8827](https://www.rfc-editor.org/rfc/rfc8827), [DTLS-SRTP, RFC 5764](https://www.rfc-editor.org/rfc/rfc5764), [SRTP, RFC 3711](https://www.rfc-editor.org/rfc/rfc3711), [ICE, RFC 8445](https://www.rfc-editor.org/rfc/rfc8445), [TURN, RFC 8656](https://www.rfc-editor.org/rfc/rfc8656): record actual negotiated behavior; a list of RFCs is not a conformance result.
- [LiveKit token lifecycle](https://docs.livekit.io/frontends/reference/tokens-grants/) and [distributed deployment](https://docs.livekit.io/transport/self-hosting/distributed/): keep raw signaling private, test revocation, and account for a room's single-node boundary.
- [LiveKit Egress requirements](https://docs.livekit.io/transport/self-hosting/egress/): recordings need separately sized/isolated workers; tests must include failures and resource exhaustion.
- [Caddy trust controls](https://caddyserver.com/docs/caddyfile/options#skip-install-trust): local trust installation is explicitly disabled. [Local HTTPS workflow](local-https.md) distinguishes verified CLI transport, opt-in trusted browser relay evidence and the remaining production checks.

The full plan retains broader requirements and framework references. This ledger does not supersede them or authorize removing gates to declare the platform finished.
