# Requirements and release gates

Reviewed against the complete [infrastructure plan](infrastructure-plan.md) and [security controls](security-controls.md), 4 October 2026. This is an implementation ledger, not a completion certificate. **External production release remains blocked.** Tests establish only their named behavior at their tested scope; an architectural setting or passing unit test does not establish production capacity, legal compliance or resilience.

Evidence is identified by checked-in implementation/tests or a reproducible validation command. Runtime reports remain local and excluded from Git because future reports can contain operational metadata. Record exact image identities, versions, timestamps and test configuration before using results as release evidence.

## Recorded local evidence

On 4 October 2026 the isolated local TLS installation passed `scripts/local.mjs health`: both origins verified the project CA and hostname with TLS 1.3; anonymous gateway entry was denied; raw signaling/API/database services had no host port mapping; every published port bound to loopback. The runtime report records exact image identities. The final silent media harness passed 44 checks through that HTTPS gateway, including real SFU publisher removal, stale-token denial, negotiated DTLS/SRTP, positive outbound video RTP, a 30-second Egress recording, verified-host password delivery, authenticated download and revocation. Independent volume inspection found the expected `MPREC001` container (73,879 bytes, mode `0600`) and no matching raw MP4. The real S3 fixture test also passed multipart ciphertext round trip, conditional overwrite prevention and version-pinned restore/delete. These checks exclude audio packet delivery, browser device behavior, load, TURN, real cloud IAM/KMS and broader failure/recovery scenarios. Re-run after rebuilding the application; these observations do not close every row above.

The isolated phone fixture separately verifies PostgreSQL reservation serialization and eight real audio-relay checks using native RTC peers as SIP stand-ins: waiting-room silence, receive-only admission, keypad mute/hand controls, host mute enforcement, explicit unmute after permission restoration, and teardown before capacity release. Generated PCM is observed only by programmatic sinks; no personal device or speaker is used. This is not native SIP/PSTN, secure-trunk negotiation, audio quality or capacity evidence. The reproducible entry point is `node scripts/phone-test.mjs`; reports remain in ignored `test-results/phone/`.

The separate native SIP fixture passed 17 checks on 4 October 2026 (run `f1532b59-c210-4d69-ad5e-239d96947584`): verified TLS and mandatory SRTP on both PBX legs, waiting-room silence, admission, two-way synthetic audio, keypad mute/hand controls, host speaking block, complete teardown before reservation release, invalid-CA/hostname rejection, unencrypted transport/media rejection, wrong credentials, and repeated/alternating digit sequences. All six code/PIN sequence pairs matched exactly; all cleanup checks passed. Two earlier attempts ended during code entry without enough evidence to identify the cause. The later successful runs do not establish sustained reliability; this remains an availability investigation and production gate. `npm run test:sip` reproduces this private local fixture and writes sanitized evidence to ignored `test-results/sip/`. Internal ARI/SFU control still uses isolated development HTTP/WS; no carrier/PSTN, public deployment, production capacity, E2EE or compliance result is implied.

## Authoritative technical boundaries

- [TLS 1.3, RFC 8446](https://www.rfc-editor.org/rfc/rfc8446), [WebRTC security, RFC 8827](https://www.rfc-editor.org/rfc/rfc8827), [DTLS-SRTP, RFC 5764](https://www.rfc-editor.org/rfc/rfc5764), [SRTP, RFC 3711](https://www.rfc-editor.org/rfc/rfc3711), [ICE, RFC 8445](https://www.rfc-editor.org/rfc/rfc8445), [TURN, RFC 8656](https://www.rfc-editor.org/rfc/rfc8656): record actual negotiated behavior; a list of RFCs is not a conformance result.
- [LiveKit token lifecycle](https://docs.livekit.io/frontends/reference/tokens-grants/) and [distributed deployment](https://docs.livekit.io/transport/self-hosting/distributed/): keep raw signaling private, test revocation, and account for a room's single-node boundary.
- [LiveKit Egress requirements](https://docs.livekit.io/transport/self-hosting/egress/): recordings need separately sized/isolated workers; tests must include failures and resource exhaustion.
- [Caddy trust controls](https://caddyserver.com/docs/caddyfile/options#skip-install-trust): local trust installation is explicitly disabled. [Local HTTPS workflow](local-https.md) distinguishes verified CLI transport from pending browser trust and media evidence.

The full plan retains broader requirements and framework references. This ledger does not supersede them or authorize removing gates to declare the platform finished.
